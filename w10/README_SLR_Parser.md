# SLR Parser in C++

## 1. Overview

This project implements a **Simple LR (SLR) parser** in C++ for arithmetic expressions. It uses a fixed ACTION/GOTO parsing table and prints each parsing step in a table containing:

- **STACK** — grammar symbols and parser states currently on the stack.
- **INPUT** — the unprocessed input tokens, including the end marker `$`.
- **ACTION** — the shift, reduce, accept, or error operation performed.

The parser accepts expressions generated by the grammar below, subject to the supplied parsing table.

## 2. Grammar

The grammar is:

```text
(1) E -> E + T
(2) E -> T
(3) T -> T * F
(4) T -> F
(5) F -> ( E )
(6) F -> id
```

Here:

- `E` represents an expression.
- `T` represents a term.
- `F` represents a factor.
- `id` represents an identifier, such as `a`, `total`, or `value2`.
- `+` and `*` are the addition and multiplication operators.
- `(` and `)` are parentheses.

This grammar gives `*` higher precedence than `+`, and makes both operators left-associative. Parentheses can override the normal precedence.

Examples of valid expressions:

```text
id
a
total + value
a + b * c
(a + b) * c
a * (b + c)
```

Examples of invalid expressions:

```text
+a
a+
a * * b
(a + b
a + b)
()
```

Whitespace is ignored, so `a+b*c` and `a + b * c` are equivalent inputs.

## 3. How an LR parser works

An LR parser reads the input **from Left to right** and constructs a **Rightmost derivation in reverse**. It uses a stack and a parsing table to decide what to do next.

The parser repeats these steps:

1. Look at the state on top of the stack.
2. Look at the next input token (the *lookahead*).
3. Find the corresponding entry in the ACTION table.
4. Perform the indicated action.

### Shift

A **shift** consumes the next input token, pushes that token onto the stack, and pushes the destination state.

For example, if the table says `s5`, the parser shifts the token and enters state `5`.

### Reduce

A **reduce** recognizes that the top of the stack matches the right-hand side of a grammar rule and replaces that right-hand side with its left-hand side.

For example:

```text
F -> id
```

When the parser reduces by this rule, it removes the `id` symbol and its associated state from the stack, then pushes `F` and the state found in the GOTO table.

The code represents reductions with negative numbers:

- `-1` means reduce by rule 1: `E -> E + T`
- `-2` means reduce by rule 2: `E -> T`
- ...
- `-6` means reduce by rule 6: `F -> id`

### GOTO

After a reduction, the parser uses the state now on top of the stack and the newly produced nonterminal (`E`, `T`, or `F`) to look up the next state in the GOTO table.

### Accept

When the parser reaches the `acc` entry (represented by `99` in the code), the entire input has been recognized as a valid expression.

### Error

If the ACTION table contains no valid shift, reduce, or accept action for the current state and lookahead token, the parser rejects the expression.

## 4. How the code is organized

### Tokenization: `tokenize()`

The tokenizer scans the input and converts it into tokens:

- Names and alphanumeric identifiers, such as `a`, `count`, and `value2`, become `id`.
- `+`, `*`, `(`, and `)` remain their own token types.
- `$` is appended automatically to mark the end of input.
- Whitespace is skipped.

For example:

```text
Input:  a + b * c
Tokens: id + id * id $
```

The original identifier text is collected, but parsing decisions use the token type `id`.

### Grammar rules: `rules[]`

The `rules` array stores the six productions. Each rule contains:

- `lhs`: the left-hand-side nonterminal.
- `length`: the number of grammar symbols on the right-hand side.
- `rhs`: the right-hand side, used when displaying the reduction.

For example, rule 3 is `T -> T*F`, which has a right-hand-side length of 3.

### ACTION table: `actionTable`

The ACTION table has one row per parser state and six columns in this order:

```text
id, +, *, (, ), $
```

The table entries mean:

- Positive number: shift to that state.
- Negative number: reduce using the rule whose number is the absolute value.
- `99`: accept.
- `0`: no valid action (error).

The table is transcribed from the assignment image.

### GOTO table: `gotoTable`

The GOTO table has three columns:

```text
E, T, F
```

It is consulted after a reduction to decide which state to push for the resulting nonterminal. `-1` indicates that no GOTO transition is defined.

### Parsing loop: `main()`

The main loop:

1. Reads the expression.
2. Tokenizes it.
3. Starts with state `0` on the stack.
4. Prints the current stack, remaining input, and action.
5. Looks up ACTION using the top state and next token.
6. Shifts, reduces, accepts, or reports an error.
7. Stops if parsing finishes or the safety step limit is reached.

The stack is represented using two vectors:

- `symbols` stores grammar symbols.
- `states` stores parser states. It always has one more state than there are symbols.

## 5. Accepted strings

The parser accepts syntactically valid arithmetic expressions generated by:

```text
E -> E + T | T
T -> T * F | F
F -> ( E ) | id
```

In practical terms:

- An expression can be a single identifier.
- Expressions can be combined using `+`.
- Terms can be combined using `*`.
- Parenthesized expressions are allowed.
- Multiplication has higher precedence than addition.
- Operators must have valid operands; empty parentheses are not allowed.

The tokenizer treats any alphanumeric word (with underscores allowed) as an identifier, so `x`, `number1`, and `total_sum` are all recognized as `id`.

**Important limitation:** This is a syntax parser, not a calculator. It does not evaluate the numerical result of an expression. It also does not support unary minus, division, decimal numbers, or other operators because those are absent from the grammar and parsing table.

## 6. Example run

Input:

```text
id+id*id
```

The parser will print a step-by-step trace with the stack, remaining input, and action. The trace begins by shifting the first `id`, then reducing `id` to `F`, `F` to `T`, and `T` to `E` as permitted by the table. It eventually recognizes the multiplication and addition structure and accepts the complete input.

The exact trace depends on the ACTION/GOTO table and the order of its shift/reduce decisions.

## 7. Compile and run

Requirements: a C++ compiler that supports C++17, such as `g++`.

```bash
g++ -std=c++17 slr.cpp -o slr
./slr
```

Then enter an expression, for example:

```text
a+b*c
```

To test other cases, try:

```text
(a+b)*c
a*(b+c)
a+b
a+
```

The first three are valid expressions; `a+` should be rejected.

## 8. Notes

- The parser uses the specific ACTION/GOTO table supplied in the assignment, rather than generating an SLR table automatically.
- The end marker `$` is appended by the tokenizer; do not type it yourself.
- `s5` means shift to state 5; `r3` means reduce by grammar rule 3; `acc` means accept.
- The parser recognizes syntax only. It does not calculate expression values.
