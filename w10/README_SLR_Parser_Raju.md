# SLR Parser in C++

## Overview

This program implements a table-driven **SLR (Simple LR) parser** in C++. It parses arithmetic expressions using predefined ACTION and GOTO tables and prints each parsing step in a table with three columns:

- **STACK** — the parser's state stack and grammar-symbol stack.
- **INPUT** — the remaining input, including the end marker `$`.
- **ACTION** — the shift, reduce, accept, or error operation performed.

The parser checks syntax; it does not calculate expression values.

## Grammar

The parser uses these productions:

```text
r1: E -> E + T
r2: E -> T
r3: T -> T * F
r4: T -> F
r5: F -> ( E )
r6: F -> id
```

Here, `E` is an expression, `T` is a term, `F` is a factor, and `id` is an identifier token. The grammar gives multiplication higher precedence than addition. Both operators are left-associative, and parentheses can change the normal order of evaluation.

## Accepted strings

Examples of accepted expressions:

```text
id
id+id
id*id
id+id*id
id*id+id
(id)
(id+id)
(id+id)*id
id*(id+id)
```

Examples of rejected expressions:

```text
+id
id+
id**id
(id+id
id+id)
()
```

The parser accepts strings generated by the grammar. In this implementation, `col()` recognizes the literal token `id`, not arbitrary names such as `count` or `total`. The program reads one whitespace-free input token using `cin >> input`, so enter expressions such as `id+id*id` without spaces.

The grammar does not include unary minus, division, decimal numbers, or other operators.

## How an LR parser works

LR means **Left-to-right scanning, Rightmost derivation in reverse**. The parser reads tokens from left to right and uses a stack and parsing tables to decide the next operation.

### Shift

A shift consumes the next input token, pushes its grammar symbol onto the symbol stack, and pushes the destination state onto the state stack. For example, `s5` means shift and enter state `5`.

### Reduce

A reduction applies a grammar production. For example, `r6` means reduce by `F -> id`. The program removes the number of symbols specified by `len[r]`, then pushes the production's left-hand-side nonterminal.

### GOTO

After a reduction, the parser consults the GOTO table using the state now on top of the stack and the resulting nonterminal (`E`, `T`, or `F`) to find the next state.

### Accept or reject

If the ACTION table says `acc`, the expression is accepted. If there is no valid ACTION entry for the current state and lookahead token, the parser rejects the input. An undefined GOTO transition also causes an error.

## Code structure

### ACTION table

`action[12][6]` contains actions for states `0` through `11`. Its columns are ordered:

```text
id, +, *, (, ), $
```

- `sN`: shift and move to state `N`.
- `rN`: reduce using production `N`.
- `acc`: accept.
- Empty string: no valid action.

### GOTO table

`goTo[12][3]` contains transitions for nonterminals in this order:

```text
E, T, F
```

The value is the next state after a reduction. `-1` means no transition is defined.

### Production arrays

- `lhs[]`: left-hand side of each production.
- `rhs[]`: right-hand side, used when displaying reductions.
- `len[]`: number of grammar symbols on the right-hand side.

For example, `E -> E + T` has length `3`.

### `col(string input)`

Maps the next input token to the correct ACTION-table column. It checks for the `id` prefix first, then `+`, `*`, `(`, `)`, and `$`.

### `ntcol(string s)`

Maps `E`, `T`, and `F` to their GOTO-table columns.

### `main()`

The main function reads the expression, appends `$`, initializes the state stack with `0`, prints the table headings, and repeatedly performs the action selected by the ACTION table. It stops on acceptance or rejection.

Two stacks are maintained:

- `states` stores parser states and starts with state `0`.
- `symbols` stores grammar symbols such as `id`, `+`, `E`, `T`, and `F`.

Temporary copies of the stacks are used to print them from bottom to top without changing the real parsing stacks.

## Example

Input:

```text
id+id*id
```

The parser prints a step-by-step trace of shifts and reductions. It processes each `id`, reduces identifiers to factors and terms as allowed by the table, handles multiplication before addition according to the grammar, and eventually prints `ACCEPT`.

## Compile and run

Save the source code as `slr.cpp`, then compile and run:

```bash
g++ -std=c++17 slr.cpp -o slr
./slr
```

Enter an expression without spaces, for example:

```text
id+id*id
```

| Input | Expected result |
|---|---|
| `id` | Accept |
| `id+id` | Accept |
| `id*id` | Accept |
| `id+id*id` | Accept |
| `(id+id)*id` | Accept |
| `id*(id+id)` | Accept |
| `id+` | Reject |
| `id**id` | Reject |
| `(id+id` | Reject |
| `()` | Reject |

## Notes

- The ACTION and GOTO tables are hard-coded; the program does not generate the SLR table automatically.
- Do not type `$`; the program appends it.
- Use the token `id` for identifiers. Inputs such as `a+b` are not recognized as identifiers by this exact implementation.
- The parser validates syntax only; it does not evaluate arithmetic expressions.
